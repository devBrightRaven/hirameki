# Task-status evidence

Shared by next's task capability and triage; runtime-specific reader launch details remain in the host entry.

The validated effective task view is authoritative when available. Raw Wrap/Journal/Handoff text adds context, not an override of indexed closure. A valid approved restore overlay makes the task visible immediately, without granting execution authority.

Without an index, match task identity, action target and scope before ordering events. A raw Open item is discovery evidence, not a confirmed active state or a reopening. Explicit unfinished or reopened evidence may support an active candidate; explicit done, withdrawn or superseded evidence excludes the same task unless a later explicit reopening exists. Unmarked or conflicting items stay visible as status uncertain and cannot be automatically archived.

Order status by task revision/supersession or an unambiguous dated explicit event. A filename, mtime, arrival order, copied text, repeated mention or frontmatter alone does not establish task state or authority. A handoff's status applies only when its scope and explicit task statement match. Never close unrelated subtasks because a parent project is closed.

Always separate confirmed active items, status uncertain and exceptions with each item's reason and sources. Recurrence is context, not proof of priority, procrastination or unfinished work. Missing/ambiguous evidence is visible, never silently removed. Do not replay old closed work as active simply because the index is unavailable.
